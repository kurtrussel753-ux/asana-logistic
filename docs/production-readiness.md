# چک‌لیست آماده‌سازی بهره‌برداری

وضعیت: نامزد انتشار؛ این سند به‌معنی استقرار یا تأیید نهایی تولید نیست. فایل مستقل production مخصوص دو سرویس اصلی است؛ LiteLLM/Langfuse خودمیزبان را با رمزهای اختصاصی و شبکهٔ خصوصی جداگانه آماده کنید یا از سرویس مدیریت‌شده استفاده کنید.

## ۱. کلیدها و تنظیمات
- کلید Tavily افشاشده را در حساب Tavily لغو و کلید جدید ایجاد کنید. کلید قبلی را برای تست مجدد استفاده نکنید.
- روی میزبان هدف `.env.production` بسازید و دسترسی فایل را به مالک محدود کنید (`chmod 600 .env.production`). این فایل در git و Docker context نادیده گرفته می‌شود. مقادیر واقعی را در نمونه‌ها یا خروجی چت قرار ندهید.
- `IFA_AUTH=password`، رمز قوی و یکتای `IFA_ADMIN_PASS`، نشانی HTTPS در `IFA_PUBLIC_URL` و رمز تصادفی مشترک حداقل ۳۲ نویسه در `IFA_RUNTIME_TOKEN` تنظیم کنید. رمز runtime را با `openssl rand -hex 32` تولید کنید.
- مدل را با `RT_LLM_PROVIDER`, `RT_LLM_URL`, `RT_LLM_MODEL`, `RT_LLM_KEY` یا دروازهٔ اختصاصی تنظیم کنید. تنظیمات مرتبط legacy را در `IFA_LLM_*` نیز برای مسیر fallback قرار دهید. پیش‌فرض حالت انتشار: `IFA_RUNTIME_MODE=shadow` و `IFA_RUNTIME_FLOWS=off`.
- `IFA_TAVILY_KEY` جدید و سقف‌های روزانه/ماهانه/عامل‌ها را تعیین کنید. `IFA_TAVILY_AGENT_OPEN=0` بماند. سقف صورت‌حساب را در حساب ارائه‌دهنده نیز اعمال کنید.
- کلیدها در فایل env مشترک به هر دو کانتینر می‌رسند؛ فایل یا خروجی `docker inspect`/compose config را منتشر نکنید. برای محیط سخت‌گیرانه فایل‌های env جداگانه و secret manager استفاده کنید.

## ۲. بررسی پیش از راه‌اندازی
```sh
npm run check:build
npm test
npm --prefix runtime ci --no-audit --no-fund
npm run test:runtime
docker compose --env-file .env.production -f deploy/compose.production.yml config --quiet
docker compose --env-file .env.production -f deploy/compose.production.yml build
```
بررسی build کانتینر و پذیرش فایل compose باید روی میزبان دارای Docker انجام شود؛ تست‌های Node جایگزین آن نیستند.

## ۳. استقرار مرحله‌ای
```sh
docker compose --env-file .env.production -f deploy/compose.production.yml up -d
curl --fail http://127.0.0.1:8080/api/health
```
- پورت سرور فقط روی loopback میزبان منتشر می‌شود؛ runtime هیچ پورت عمومی ندارد. HTTPS reverse proxy، محدودیت اندازهٔ درخواست، rate limiting و قواعد فایروال را روی میزبان تنظیم کنید. TLS termination در این فایل فراهم نشده است.
- روی نصب موجود، تغییر `IFA_ADMIN_PASS` را به‌معنی تغییر خودکار رمز ذخیره‌شده تلقی نکنید؛ رمز admin را از روش رسمی برنامه تغییر دهید و ورود با رمز قبلی را بررسی کنید.
- فقط یک replica سرور با volume پایدار اجرا کنید. پشتیبان‌گیری از SQLite را با توقف نوشتن یا ابزار backup سازگار انجام دهید؛ کپی سادهٔ فایل زنده قابل اتکا نیست.

## ۴. معیار پذیرش
- ورود ناشناس به مسیرهای حساس رد شود؛ viewer نتواند تأیید مالی یا اقدام خارجی انجام دهد.
- یک سؤال نرخ حمل با منابع ابزار پاسخ داده شود؛ خروجی shadow با legacy مقایسه شود.
- استعلام خرید و پرداخت مالی بدون تأیید انسانی هیچ اقدام خارجی انجام ندهند؛ حالت تأیید و رد هر دو تست شوند.
- مرکز تحقیق: یک شرکت با دامنهٔ معلوم، یک شرکت هم‌نام بدون دامنه و یک موضوع رسمی را آزمایش کنید؛ توقف هویت، کیفیت ارجاع‌ها، تماس‌ها، حریم خصوصی در مسیرهای قدیمی، زمان‌بندی و سقف هر کار را بررسی کنید. راهنما: [research-desk.md](research-desk.md).
- یک پژوهش Tavily کامل شود و منابع/مصرف در UI ظاهر شوند؛ سقف‌ها و kill switch آزمایش شوند.
- توقف runtime باعث fallback کنترل‌شده شود؛ پس از restart، گردش‌کار منتظر تأیید و پژوهش در حال اجرا قابل پیگیری باشند.
- بازیابی نسخهٔ پشتیبان در محیط جداگانه با موفقیت انجام شود. سناریوهای واقعی حمل‌ونقل توسط مالک محصول تأیید شوند.
- حداقل یک دورهٔ پایش shadow را بگذرانید؛ سپس `primary` و فعال‌سازی flows را جداگانه و با تصمیم انسانی انجام دهید.

## ۵. بازگشت و پایش
- برای توقف واگذاری ایجنت‌ها: `IFA_RUNTIME_MODE=off` و `IFA_RUNTIME_FLOWS=off` و بازسازی کانتینرهای وابسته. اجرای گردش‌کارهای قبلاً شروع‌شده ممکن است ادامه داشته باشد؛ برای توقف فوری، runtime را متوقف و kill/pause عامل‌ها و زمان‌بندی‌ها را از سرور اعمال کنید.
- برای توقف Tavily: `IFA_TAVILY_OFF=1` و بازسازی کانتینر سرور. این گزینه پژوهش قبلاً پذیرفته‌شده در سرویس Tavily را لغو نمی‌کند.
- healthcheck، خطاهای اتصال، تأخیر، مصرف توکن/کردیت، صف تأیید و اختلاف پاسخ shadow را پایش کنید؛ هشدار بیرونی باید روی میزبان/سامانهٔ پایش تنظیم شود.
- قبل از بازگشت نسخهٔ کد، سازگاری schema دیتابیس را بررسی کنید؛ هیچ migration را بدون نسخهٔ پشتیبان معکوس نکنید. از `down -v` استفاده نکنید، چون داده را حذف می‌کند.
